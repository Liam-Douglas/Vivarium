One layout, three widths

Vivarium’s entire responsive treatment today is four things: card grids go 2 → 3 → 4 columns, the bottom padding drops, the FAB hides, and the sidebar appears. Everything else is a phone layout centred in a column. The proposal is not a second design for the web — it is the same components, told what to do with extra width.

Width buys columns, not whitespace.

Every screen here already stores more per record than a 390px phone can show. When the viewport grows, the fields that were truncated get their own column — the row does not stretch and the gutters do not grow. When it shrinks, those columns fold back under the title. Same component, same data, same tap targets.

The ladder

Phone

< 768px

Bottom nav. FAB. One column. Rows stack to two lines. Charts become sparklines.

Tablet

768 – 1023px

Sidebar replaces bottom nav. Split button replaces FAB. Still one content column; grids go 3-up.

Desktop

≥ 1024px

Two columns: primary work + a rail. Rows unfold into columns. Records become tables. Content caps at 1240px.

Tailwind already gives you these as md: and lg: — the app just does not use them for anything but grid columns.

True at every width

✓

Every action is reachable on both. No capability may exist only above or only below a breakpoint.

✓

Every destination is reachable on both. The bottom nav and the sidebar must agree on where you can go.

✓

Interactive targets stay 44px. A mouse does not earn a smaller button; it just tolerates one.

✓

One token set. Same type ramp, radii, surfaces and status colours; no desktop-only palette.

The parity break to fix first

The sidebar has six destinations; the bottom nav has four. Feeding and Stats cannot be reached on a phone at all — on a mobile-first PWA. Proposal: five tabs, Home / Animals / Feeding / Stats / More, with Expenses and Settings under More.

Worth checking while you are in there: FeederInventory.tsx (645 lines) and FeedingCalendar.tsx (209 lines) are not imported anywhere — their routes redirect to Expenses and Feeding, and feeder stock now lives inside the Expenses page. They look like dead code rather than missing nav.
